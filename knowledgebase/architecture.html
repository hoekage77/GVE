Request Router

The entry point that processes all incoming user requests through a 4-stage pipeline:

1
Intent Parser
Parses natural language into structured intent with entities, constraints, and confidence scores. Detects greetings, capability questions, and small talk.
2
Context Manager
Maintains conversation history and scene context across multiple turns. Tracks current artifact, revision pointers, and undo/redo state.
3
Skill Selector
Scores and ranks skills based on domain match, capability coverage, constraints, execution reliability, and warm pool availability.
4
Session Manager
Manages user sessions with file-based persistence. Handles session creation, message appending, and scene versioning.

Conditional Routing Logic

// From orchestrator.js - conditional edges
function routeFromValidation(state) {
  if (state.skip_validation_if_degraded && state.degraded) {
    return "execute_code";
  }
  if (state.validation_result?.passed) {
    return "execute_code";
  }
  if ((state.validation_result?.attempt || 0) < 2) {
    return "agent_self_debug";  // Try to fix
  }
  return "execute_code";  // Proceed anyway (may fail)
}

function routeFromExecution(state) {
  if (state.execution_result?.status === "completed") {
    return "sync_state";
  }
  if ((state.execution_result?.attempt || 0) < 2) {
    return "retry_recovery";
  }
  return "degraded_mode";
}

Sandbox Pool Architecture

The SandboxPoolManager provides resilient sandbox lifecycle management with dual-tier creation strategy and circuit breaker protection.

Sandbox Acquisition Flow

1
Check Warm Pool
First, try to acquire from pre-warmed sandboxes (idleSandbacks). These are ready-to-use with base dependencies pre-installed.
2
Direct Create (Fast Path)
If circuit is closed, try direct workspace creation (10s timeout). Uses custom image if configured. Fast but may fail.
3
Fallback Create (Reliable)
If direct fails, use fallback creation (25s timeout). More reliable but slower. Includes retry logic.
4
Skill Setup
Install skill-specific dependencies, mount templates, and start runtime.

Circuit Breaker Pattern

// Circuit breaker for direct create
class CircuitBreaker {
  failureThreshold = 3;      // Open after 3 failures
  windowMs = 120000;         // Within 2 minutes
  cooldownMs = 90000;        // Stay open for 90s
  
  failures = [];             // Rolling window
  openUntilMs = 0;           // Circuit state
  
  recordFailure() {
    failures.push(Date.now());
    failures = failures.filter(t => t > Date.now() - windowMs);
    if (failures.length >= threshold) {
      openUntilMs = Date.now() + cooldownMs;
    }
  }
  
  isOpen() {
    return Date.now() < openUntilMs;
  }
}

Persistence Strategy

Sessions are persisted to disk using atomic writes with debouncing to minimize I/O while ensuring durability. 

// File-based persistence (session-state.js)
const PERSISTENCE_DEBOUNCE_MS = 500;
const PERSISTENCE_DIR = ".data/sessions";

async function persistSession(sessionId, state) {
  const filePath = `${PERSISTENCE_DIR}/${sessionId}.json`;
  const tempPath = `${filePath}.tmp`;
  
  // Atomic write
  await fs.writeFile(tempPath, JSON.stringify(state, null, 2));
  await fs.rename(tempPath, filePath);
}

// Debounced save
function saveSession(sessionId) {
  clearTimeout(saveTimeouts[sessionId]);
  saveTimeouts[sessionId] = setTimeout(() => {
    persistSession(sessionId, sessions[sessionId]);
  }, PERSISTENCE_DEBOUNCE_MS);
}

Error Handling & Recovery

Error Classification

Error Type Recoverable Strategy
AMBIGUOUS_INTENT Yes Clarify with user, suggest options
SKILL_NOT_FOUND Yes Suggest alternatives, use default
GENERATION_FAILED Yes Retry (max 3), simplify prompt, use example
VALIDATION_FAILED Yes Agent self-debug loop (max 2 iterations)

SANDBOX_UNAVAILABLE Yes Wait, scale up, queue request

Agent Self-Debug Loop

When validation fails, the system attempts automatic code fixing using an agent loop with validation and execution tools. 

// Agent loop for self-debugging (agent-runner.js)
async function runAgentLoop(context, tools) {
  const maxIterations = 2;
  
  for (let i = 0; i < maxIterations; i++) {
    // 1. Analyze error
    const analysis = await llm.analyze({
      code: context.code,
      error: context.error,
      validation: context.validation
    });
    
    // 2. Generate fix
    const fix = await llm.generateFix({
      analysis,
      skill: context.skill
    });
    
    // 3. Validate fix
    const validation = await tools.validate_code(fix.code);
    if (validation.passed) {
      return { success: true, code: fix.code };
    }
    
    // 4. Update context for next iteration
    context.error = validation.error;
    context.code = fix.code;
  }
  
  return { success: false, attempts: maxIterations };
}

Deterministic Fixes

Common API errors are automatically patched without LLM intervention for faster recovery. 

// Deterministic code patches (orchestrator.js)
const DETERMINISTIC_FIXES = [
  {
    // Fix: setScalar is not a function
    pattern: /\.setScalar\(/g,
    replacement: '.set('
  },
  {
    // Fix: Invalid constructor names
    pattern: /new THREE\.([A-Z][a-zA-Z]+)BufferGeometry/g,
    replacement: (match, name) => {
      const validName = normalizeGeometryName(name);
      return `new THREE.${validName}Geometry`;
    }
  },
  {
    // Fix: Missing imports for p5.js
    pattern: /^(?!.*import.*p5).*createCanvas/m,
    replacement: 'import p5 from "p5";\n$&'
  }
];

function applyDeterministicFixes(code) {
  for (const fix of DETERMINISTIC_FIXES) {
    if (fix.pattern.test(code)) {
      code = code.replace(fix.pattern, fix.replacement);
    }
  }
  return code;
}
