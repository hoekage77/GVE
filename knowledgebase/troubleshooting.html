Troubleshooting

Common issues and solutions

Sandbox Issues

Sandbox Acquire Timeout

Symptom: Requests fail with "Sandbox acquire timeout" or take very long.

# Check Daytona credentials
curl -H "Authorization: $DAYTONA_API_KEY" \
  https://api.daytona.io/v1/workspaces

# Verify environment variables
node -e "console.log(process.env.DAYTONA_API_KEY)"
  • Verify DAYTONA_API_KEY is set correctly
  • Check Daytona service status
  • Increase DAYTONA_FALLBACK_CREATE_TIMEOUT_SECONDS
  • Check network connectivity to Daytona API

Circuit Breaker Open

Symptom: Logs show "Circuit breaker is open, using fallback".

  • This is normal behavior after multiple direct create failures
  • System automatically recovers after cooldown period
  • If frequent, check Daytona API stability
  • Consider increasing DAYTONA_DIRECT_CIRCUIT_BREAKER_THRESHOLD

Warm Pool Empty

Symptom: Every request provisions a new sandbox (slow).

# Check pool status in logs
# Look for "prewarm" events

# Increase pool size
DAYTONA_PREWARM_SIZE=3

LLM Provider Issues

All LLM Providers Exhausted

Symptom: "All LLM providers exhausted" error.

  • Verify at least one API key is set correctly
  • Check API key quotas and billing status
  • Review rate limit logs for specific providers
  • Configure multiple providers for failover

Rate Limiting

Symptom: Frequent 429 errors or slow responses.

# Provider rate limits:
# - Moonshot: 5 req/min
# - DeepSeek: 10 req/min  
# - Groq: 30 req/min
# - Gemini: 60 req/min

# Solution: Configure multiple providers
MOONSHOT_API_KEY=...
GROQ_API_KEY=...
GEMINI_API_KEY=...

Generation Issues

Code Validation Failures

Symptom: Generation fails at validation step repeatedly.

  • Check if code has syntax errors in logs
  • Review validation error details in orchestration trace
  • System auto-retries with agent self-debug (max 2 attempts)
  • If persistent, check skill templates are correctly mounted

Runtime Execution Errors

Symptom: Code validates but fails in sandbox.

# Common errors:
# - "THREE is not defined" -> Skill not loaded properly
# - "Cannot read property of undefined" -> Code references missing object
# - "setScalar is not a function" -> API mismatch (auto-fixed by system)

# Check:
1. Sandbox skill installation logs
2. Runner script execution output
3. Code for API compatibility with skill version

Empty Scene Output

Symptom: Execution succeeds but scene is empty/black.

  • Check renderCount in execution result (should be > 0)
  • Verify camera position in generated code
  • Check for background color overriding content
  • Ensure objects are added to scene

WebSocket Issues

Connection Drops

Symptom: WebSocket connection repeatedly disconnects.

# Check server WebSocket logs
# Look for: connection:ready, session:resumed

# Common causes:
1. Proxy timeout (nginx: proxy_read_timeout)
2. Firewall blocking WebSocket upgrade
3. Client not responding to ping frames

# Solutions:
- Configure proxy timeouts > 60s
- Enable WebSocket support in load balancer
- Implement client-side heartbeat

Event Replay Failures

Symptom: Session resume shows stale or missing events.

  • Check event sequence numbers in logs
  • Verify lastSeq sent by client on resume
  • Replay buffer size: 2000 events (configurable)
  • If buffer exceeded, client gets full session state snapshot

Session Issues

Session Not Found

Symptom: "Session not found" errors.

# Check session persistence
ls -la apps/.data/sessions/

# Verify session file exists
cat apps/.data/sessions/{sessionId}.json

# Common causes:
1. Session expired (no expiration currently)
2. Session file corrupted
3. Server restarted without persistence mounted

Version Navigation Broken

Symptom: Undo/redo or artifact navigation doesn't work.

  • Check artifactPointer and revisionPointer values
  • Verify version chain is intact (no missing parents)
  • Review session state for corruption

Performance Issues

Slow Generation Times

Symptom: Turn takes > 30 seconds consistently.

# Diagnostic steps:

1. Check sandbox acquisition time
   - Look for "acquire" duration in logs
   - Should be < 5s with warm pool

2. Check LLM response time
   - Provider latency varies
   - Consider switching to faster provider (Groq)

3. Check validation/execution time
   - Complex code takes longer to validate
   - Execution timeout is 30s max

# Optimizations:
DAYTONA_PREWARM_SIZE=3          # More warm sandboxes
FAST_MODE=true                  # Enable fast mode
ENABLE_ASYNC_THINKING=true      # Parallel thinking

High Memory Usage

Symptom: Server memory continuously grows.

  • Check for memory leaks in session storage
  • Verify old sessions are being cleaned up
  • Monitor sandbox pool size (shouldn't grow unbounded)
  • Check for stuck sandboxes in "active" state
