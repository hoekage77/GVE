Configuration & Deployment

Environment setup, deployment, and operations

Environment Variables

Daytona Sandbox Configuration

Variable Required Default Description
DAYTONA_API_KEY Yes* - API key for Daytona SDK authentication
DAYTONA_JWT_TOKEN Alternative* - JWT token for authentication (with DAYTONA_ORG_ID)
DAYTONA_ORG_ID With JWT - Organization ID for JWT authentication
DAYTONA_PREWARM_SIZE No 1 Number of sandboxes to keep warm
DAYTONA_PREWARM_REPLENISH_THRESHOLD No 1.0 Threshold to trigger pool replenishment (0-1)
DAYTONA_PREWARM_CHECK_INTERVAL_SECONDS No 15 Seconds between pool maintenance checks
DAYTONA_DIRECT_CREATE_TIMEOUT_SECONDS No 10 Timeout for fast-path sandbox creation
DAYTONA_FALLBACK_CREATE_TIMEOUT_SECONDS No 25 Timeout for fallback sandbox creation
DAYTONA_DIRECT_SKIP_BUDGET_MS No 4000 Skip direct create if budget below this (ms)
DAYTONA_ACQUIRE_RETRY_ATTEMPTS No 2 Number of retry attempts for provisioning
DAYTONA_DIRECT_CIRCUIT_BREAKER_THRESHOLD No 3 Failures before opening circuit breaker
DAYTONA_DIRECT_CIRCUIT_BREAKER_WINDOW_MS No 120000 Rolling window for circuit breaker (ms)
DAYTONA_DIRECT_CIRCUIT_BREAKER_COOLDOWN_MS No 90000 Cooldown before closing circuit (ms)
DAYTONA_DIRECT_CREATE_IMAGE No - Custom Docker image for direct create
DAYTONA_DIRECT_CREATE_IMAGE_MANIM No - Manim-only custom Docker image for direct create (preferred for LaTeX workloads)

* Either DAYTONA_API_KEY or (DAYTONA_JWT_TOKEN + DAYTONA_ORG_ID) is required

Development Setup

Prerequisites

  • Node.js 20+
  • npm 10+
  • Daytona account with API key
  • At least one LLM provider API key

Installation

# Clone repository
git clone 
cd dosco-visual-engine

# Install dependencies
npm install

# Set up environment
cp apps/server/server/.env.example apps/server/server/.env
# Edit .env with your API keys

# Run development servers
npm run dev:server  # Terminal 1 - Backend on port 8000
npm run dev:web     # Terminal 2 - Frontend on port 5173

Development Server Proxy

The Vite dev server is configured to proxy API calls:

// vite.config.ts
export default defineConfig({
  server: {
    port: 5173,
    proxy: {
      "/api": { target: "http://localhost:8000" },
      "/ws": { target: "ws://localhost:8000", ws: true }
    }
  }
});

Production Deployment

Build

# Build all packages
npm run build

# Output:
# - apps/web/dist/        # Static frontend files
# - apps/server/dist/     # Compiled server (if using TypeScript)
# - packages/*/dist/      # Compiled packages

Docker Deployment

# Dockerfile
FROM node:20-alpine

WORKDIR /app

# Copy package files
COPY package*.json ./
COPY apps/server/package*.json ./apps/server/
COPY packages/*/package*.json ./packages/*/

# Install dependencies
RUN npm ci --only=production

# Copy built files
COPY apps/web/dist ./apps/web/dist
COPY apps/server ./apps/server
COPY packages ./packages

# Expose ports
EXPOSE 8000

# Start server
CMD ["node", "apps/server/server/index.js"]

# docker-compose.yml

Static Frontend Hosting

The built frontend (apps/web/dist) can be served from any static host (CDN, S3, Netlify, Vercel, etc.). Configure these environment variables: 

VITE_API_BASE_URL=https://api.yourdomain.com
VITE_WS_BASE_URL=wss://api.yourdomain.com

Backup & Recovery

Session Persistence

Sessions are automatically persisted to apps/.data/sessions/ with atomic file writes. To back up sessions: 

# Backup sessions
tar -czf sessions-backup-$(date +%Y%m%d).tar.gz apps/.data/sessions/

# Restore sessions
tar -xzf sessions-backup-20240326.tar.gz -C /

Disaster Recovery

  1. Backup .data/ directory regularly
  2. Store API keys securely (use secrets manager)
  3. Use warm pool to reduce cold start impact
  4. Configure multiple LLM providers for failover

Scaling Considerations

Horizontal Scaling

  • Stateless Server: Server instances are stateless; session state is stored on disk and can be shared via NFS or similar.
  • Load Balancing: Use sticky sessions for WebSocket connections or implement shared session store.
  • Sandbox Pool: Each server instance manages its own sandbox pool; consider pooling at the cluster level for better utilization.

Resource Planning

Component CPU Memory Per
Server (idle) 0.1 cores 256 MB instance
Server (active) 0.5 cores 512 MB 10 concurrent users
Sandbox (threejs) 1 core 512 MB sandbox
Sandbox (p5js/d3js) 1 core 256 MB sandbox

Performance Tuning

  • Increase DAYTONA_PREWARM_SIZE for high-traffic scenarios
  • Adjust DAYTONA_DIRECT_SKIP_BUDGET_MS based on latency requirements
  • Enable FAST_MODE for lower latency (may reduce some features)
  • Configure caching layers for LLM responses
